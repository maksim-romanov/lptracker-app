Constitution Draft for review

Twelve shared principles, then the rules each platform adds. When two collide, the order is: accessibility, platform convention, token contract, brand expression, sameness across platforms.

  1. One contract, native implementationsShare tokens, names, anatomy, states, springs and accessibility text. Never share code or pixels.
  2. Ownership decides the buildOurs, native with our tokens, or native only. If the OS owns the behavior, the control is native.
  3. Platform idioms win tiesBack gesture, navigation, switch versus checkbox, title alignment follow the platform.
  4. Tokens only, three tiersReference, system, component. No literal colour, size or duration in a component.
  5. Content carries the brandAccent on the primary action, status and the switch. Display font for headings and figures only.
  6. Every state is specifiedRest, pressed, focus, disabled, loading, error, and stale or empty for data. Never colour alone.
  7. Accessibility is a gate44 pt, 48 dp or 24 px minimum targets. Text 4.5 to 1. Edges, tracks and focus 3 to 1. 200% text.
  8. Motion comes from tokensSoft springs, no bounce on controls. Reduced motion swaps movement for a fade. One notable motion per screen.
  9. The server owns numbersComponents format and show. They never compute. Tabular digits.
  10. Specify before buildingA short spec per component: anatomy, states, tokens, motion, accessibility, mapping, test.
  11. Keep the kit smallA component earns its place when two screens need it. Prefer native.
  12. Test the contract, not pixelsContrast pairs, targets, large-text snapshots, token drift. No cross-platform pixel diff.
Web
  • HTML first, ARIA last. A role promises keyboard behavior.
  • Works without JavaScript. Scripts only enhance.
  • States from CSS: :user-invalid, :focus-visible, :checked.
  • Hover is an enhancement. Focus is never hidden by sticky bars.
  • Reduce, do not remove motion.
iOS
  • Standard components first. Customise size, placement and behavior as little as possible.
  • Dynamic Type to at least 200%, text from 11 pt up.
  • Back swipe, sheets and large titles stay system.
  • No checkbox. Use a switch or a checkmark row.
Android
  • Material 3 shapes and ripple for native controls, our tokens for colour.
  • 48 dp targets, Role and content descriptions.
  • System back is never shadowed by a gesture.
  • Brand colours, not dynamic colour.

Buttons Ours

One look everywhere. Feedback differs: web and iOS scale to 97% (iOS also dims), Android shows a ripple from the touch point. Loading sets aria-busy and changes the label. At most two prominent buttons per screen, and a destructive action never takes the primary style.

Fields Native + tokens

The edge is a token with at least 3 to 1 against the page, so a field is visible without its fill. Web uses native validation. iOS keeps a filled container and a clear button. Android keeps the outlined field with a floating label. Type an address by hand to see validation.

Selection Native + tokens Chips ours

State never rests on colour alone: the switch moves, the checkbox shows a tick, the segment moves a thumb or shows a check, the selected chip changes fill. All of it works from native inputs, with no script.

Sheets, dialogs and menus Native + tokens

The same three on every platform, all live: a sheet with detents, a confirmation, and a menu. Web uses the browser dialog and popover. On iOS and Android the system component is drawn here as a faithful stand-in, inside a phone screen. Every sheet can be dragged, and every drag has a button.

Messages Banner ours Toast native + tokens

A banner stays until the cause is gone or the person dismisses it, and looks the same everywhere. A toast confirms something that already happened and offers one undo. It never carries information the screen does not show elsewhere.

Navigation Native only

We do not restyle it. On the web the sticky bar must not cover what has focus, so the scroll area sets scroll-padding-top: press Tab inside it. iOS keeps the large title and the back chevron. Android keeps the left-aligned app bar and the back arrow.

Status and range Ours

The signature pieces, identical on every platform. A status always carries a word and a shape. The knob becomes a diamond out of range. The value is formatted by the server and only displayed.

Contrast

Measured on the rendered colours of the current palette. Text needs 4.5 to 1. Edges, switch tracks and focus rings need 3 to 1. Disabled controls are exempt.
