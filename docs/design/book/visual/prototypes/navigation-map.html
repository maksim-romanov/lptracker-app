Accessibility along the map

The rules every arrow follows. Per arrow, the Focus line in the detail panel says where focus goes. Source: docs/decisions/0022-accessibility.md and docs/research/repo/accessibility-all-devices.md.

  • Every screen starts with a title, and that is where focus and the screen reader go on arrival.
  • A sheet takes focus, hides the page behind it, and gives focus back to the control that opened it. Every swipe has a button.
  • Tabs are never hidden or disabled. A gated tab explains why and offers the next step.
  • Selecting a row in a split layout does not move focus. Opening a screen does.
  • Live prices change in place, so the screen reader does not lose its place. Only important changes are announced.
  • A widget is read as one sentence and opens one place. Stale and failed widgets still open the screen, which refreshes. Status is a word and a shape, never only colour.
  • iPad and Mac work from the keyboard. Every command is in the menu bar with its shortcut.

One pattern that scales: zoom from the source

When you open a position, the tapped card grows into the detail screen, and back shrinks it into the same card. Each system has a first-party version, so the pattern costs one named element per platform and no custom animation engine.

Decisions this draft needs

Each has a recommendation. They change the map.

  1. Position detail: a pushed screen or a sheet on phones? Recommendation: a pushed screen. Apple says sheets are for a scoped task and should not hold navigation. Zoom from source works for pushes on all three platforms and not across an Android bottom sheet. Sheets stay for Add wallet, alert rule and sign-in. On wide layouts the detail is a column.
  2. Three tabs: Portfolio, Alerts, Settings. Apple asks for as few as needed and no overflow. Wallets are managed in Settings.
  3. A wallet scope switcher in the Portfolio header ("All wallets") for people with several wallets. Two taps to Wallets is slow for the main object, but it adds a menu to the map. Recommendation: add it after the first beta, with a wallet filter.
  4. Range is a section of the detail, not a screen. This version folds it in.
  5. Guests and alerts. Alerts need an account, so the tab shows an empty state with a sign-in action. It is not disabled and not hidden. Mac has no push in the MVP and says so.
  6. Where entries land. A push lands in Alerts › Detail. Home Screen widgets, Lock Screen rows, links and Siri land in Portfolio › Detail. The Lock Screen circular and inline widgets open Alerts. An empty widget opens Add wallet. Confirm.
  7. Widgets: one tap target each. Home Screen Small and Medium, and the three Lock Screen shapes, each open one place. No buttons inside a widget, so the whole widget is one control for VoiceOver. Design: the VoidX Widgets artifact.
  8. Mac and iPad are a separate pass after the iPhone flows: sidebar, menu bar commands, Settings window, keyboard. The wide layout above is the structure, not the polish.
