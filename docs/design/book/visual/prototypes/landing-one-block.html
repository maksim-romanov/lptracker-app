Notes for build: data, states, accessibility, platform mechanics

Data on screen (position model)

  • Portfolio: totals.all (owed fees sum is derived on the server too), positions[], scopes[] for the partial-failure banner, asOf, readBlock.
  • Card: pair from pool.token0/1, fee and chain, value, principal amounts, range (lower, upper, barPosition, status).
  • Position: owed amounts only when feeAccrual.mode is claimable; display.details[] renders the Details box, so a new family needs no app release.
  • Clients format strings; nothing is computed on the device.

States covered

  • First visit with example data, Add wallet (paste, looking up, ready, not an address, name not found, already watched, guest limit), reading each chain, no positions, Wallets (guest at the limit, paused after a downgrade, remove confirmation), loading, partial failure, out of range, partial value (never $0), unlisted-token badge.
  • Not drawn yet: signed-in header, sign-in sheet, retired and not-configured scopes, truncated scope, low amounts confidence, stale price age, QR scan, Android.

Accessibility

  • One h1 per screen; focus goes to it on push. Back returns focus to the tapped row.
  • Status is a word and a shape (dot, diamond), never colour alone; the range bar has a text label with the numbers.
  • Muted text is a solid colour, measured at 4.5:1 or better on all four fills in both schemes; token marks are decorative and hidden from the screen reader.
  • Targets are 44 pt or more; filters and view switch are real buttons with pressed state.
  • Live prices update in place; only a status change is announced.

Platform mechanics

  • Web: real pages and links; the Drawer opens in place, Open is a link to the position page with a cross-document view transition. Cards and Rows are one list with two layouts.
  • iPhone: Rows by default; push with zoom from the tapped row (matchedTransitionSource and zoom transition); tab bar stays. Reduce Motion becomes a cross-fade.
  • Android: the same screens with Navigation 3 and shared bounds; the position screen is a destination, not a sheet.
  • iPad and Mac reuse these as list and detail columns (see the Mac and iPad pass).
