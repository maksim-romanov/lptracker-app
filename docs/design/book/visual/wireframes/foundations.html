How to use this set

Four pages describe the product structure with no visual design. An agent building the app from scratch follows them for structure and names, and leaves everything marked pending for a later design pass.

Fixed herePending (design pass later)
  • Screens, regions and their order
  • Component anatomy, states and behaviour
  • Token names, layers and contexts
  • Size rules, spacing scale, touch targets
  • Data each element shows
  • Accessibility and motion rules
  • Colour values and palette
  • Typeface and weights
  • Corner shapes, borders, shadows, glass
  • Icons, illustration, logos beyond data
  • Final copy and imagery
  • Motion character beyond the shared tokens

Placeholder policy. Until the design pass, build with the platform system font, the Scheme values on the colour page (neutral placeholders for the rest), flat rectangles and the shared motion tokens. The colours in these wireframe pages are a documentation style for readability; they are not the product palette and no implementation value comes from them. Every visual value comes from a token, never from a literal, so the design pass changes token values and touches no component code. Mark any visual choice that is not in a token with a design-pending comment.

Relation to existing decisions. The token pipeline is ADR 0027 (DTCG, Terrazzo), motion is ADR 0023, accessibility is ADR 0022, the Ghost look is ADR 0055. This set does not depend on the Ghost values. The Ghost colours in ADR 0027 are one possible value set for the roles below.

Token architecture

Three layers. A component may use only the layer below it, so a visual change is made in one place.

1. PrimitiveRaw scale values: a grey ramp, a type ramp, a space ramp. Named by step, not by use. grey.500, size.17, space.lg
2. SemanticA role in the product, per context. Components use this layer. color.on-surface, color.surface-container-lowest, space.inset.md
3. ComponentOptional, only where one component needs its own value. button.primary.fill points to a semantic token.

Rule. Component code references semantic or component tokens. Primitive tokens are referenced only by the semantic layer. A raw hex, px or ms value in a component is a defect.

RuleDetail
NumbersEvery number uses tabular digits, set by font.feature.tabular-nums (on for display-*, label and caption; switched on for numbers in body). The generator emits tabular-nums on web, tnum in Compose and monospacedDigit in SwiftUI. A value never changes width when digits change.
Text sizeBody follows the platform default (17 pt iOS, 16 sp Android, 1 rem web). Roles scale with system text size: Dynamic Type to AX5, font scale to 2.0, rem on web. Mac has no text scaling; windows and display zoom cover it.
ReflowNo fixed heights on text. At the largest sizes a row stacks (name above value) instead of truncating. Status, value and amounts are never truncated; pair names may wrap to two lines.
Weightsfont.weight.regular medium semibold bold as tokens. Bold Text on Apple maps one step heavier.
Line lengthRunning text at most 65 characters. Headlines use balanced wrapping.
CaseSentence case in the interface. Uppercase only for tiny section labels, with letter spacing.
Facefont.family.display, font.family.body, font.family.numeric. All three start as the system font. Only the numeric face needs tabular digits.

Pending: typeface, weights actually used, tracking, optical sizes. The role table above is the structural default and can be tuned without touching components.

Font independence

The typeface is not decided and will change. Nothing in a layout may depend on the metrics of one face. Swapping the face is a token change plus a check, never a layout change.

RuleWhy it keeps a swap cheap
Roles carry size, line height and weight; the face is one tokenfont.family.* is the only place a face is named. Components never name a face.
Per-face tuning lives in tokensfont.size-adjust (scale a face so its x-height matches the role), font.line-height-adjust, font.tracking.*, font.weight.map. A new face sets these; roles stay unchanged.
No width depends on glyph widthsContainers size by content, grid and flex, not by a measured string. No fixed widths for text. Avoid the ch unit for layout; use rem, em or columns.
No truncation as a layout toolRows stack or wrap at large text sizes; the layout works with a face that is 15 percent wider or narrower.
Numbers need tabular digitsAny candidate face must provide tabular figures. If it does not, the font.family.numeric token points to a different face. Numbers are the only text with this hard requirement.
Fallback with matched metricsWeb emits a fallback face with size-adjust and metric overrides so the swap does not shift layout. Native uses the system font until the bundled face loads.
ScriptsLatin and Simplified Chinese at launch. Chinese always uses the platform face; the role sizes still apply. A candidate is checked for Latin Extended and Cyrillic gaps before use.
LicenceBundled faces must be open licence (OFL or similar). Self-hosted, subsetted, never a runtime CDN.

Checklist when the face changes

StepCheck
1Set the family, weights and the adjust tokens. Do not edit components.
2Tabular figures present and aligned in every role that carries numbers.
3Snapshot every screen at the largest text size (AX5, scale 2.0, 200 percent) and at the default: no clipping, no stacked row left side by side.
4Font bytes on the critical path stay within the budget; fallback shift measured below the layout shift budget.
5Contrast test passes for every ink and surface pair in both themes (weight can change legibility).
6Hero number fits in its box with the longest realistic value (for example 7 digits and a currency mark).

Pending: the face itself. The research shortlist and the owner comparison live in the typeface note; this page is correct for any face that passes the checklist.

NamesT-shirt steps xxs to xxxl, eight in all. Do not add a step; add a semantic token instead.
UseComponents use the semantic tokens only; the scale is for building them.
PlatformsCSS --space-md (not --spacing-*, which Tailwind treats as a numeric multiplier); Swift Spacing.md; Compose Spacing.md as Dp.
Text sizePage margin and grid do not scale. Spacing tied to text (control padding, icon gap) scales with system text size.

Rule. Spacing between siblings uses gap on the container, not margins on the children. Content never touches the screen edge: the margin token plus the safe area is the minimum.

Motion

Already decided in ADR 0023. Components name a motion token and never a duration.

TokenValueUse
instant fast base slow0, 150, 250, 400 msDurations
standard emphasized exitcubic-bezier curvesEasings
briskspring, 0.22 s, bounce 0.4Presses, small elements
gentlespring, 0.44 s, bounce 0.2Sheets and transitions
flipspring, 0.63 s, bounce 0.375Drawer on web Cards, provisional
intent110 msHover delay before details open
stagger30 ms per item, at most 8Lists; 0 when reduced

Rules. Only transform and opacity animate on web. Under reduced motion every spatial change becomes a short crossfade. No logic waits for an animation to finish. Live values change in place; only a status change is announced.
