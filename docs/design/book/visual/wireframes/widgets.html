Widget rules

One position per widget. A widget is a snapshot of data the app has already read. It is never a place where numbers are calculated.

Fixed. Families, regions, data, states, tap targets, refresh behaviour and accessibility. Pending: colour, type face, corner shape, surface treatment, and the look under the system tint.

RuleDetail
One tap targetThe whole widget opens one place: the position it shows. No buttons inside. A widget showing a count opens Alerts.
No numbers computedValues are strings formatted by the server and saved by the app into the shared container. The widget only lays them out.
StatusA word and a shape, so it survives single-tint and monochrome rendering.
Never blankA widget that cannot refresh keeps its last values and shows their age. It never shows an empty shell for an existing position.
No network for authThe widget does not refresh tokens and does not fetch flags. It reads the snapshot and code defaults.
Unpriced tokenShows the token amount; a total marked "partial" or "n/a". Never zero.
SizeDesigned as ratios. The system chooses the point size per device; layouts scale and never use fixed pixel positions.

Choosing what a widget shows

The person picks once when adding the widget.

OptionValuesDefault
PositionThe worst position, or a chosen positionThe worst
Block colourAutomatic, or one of the four fillsAutomatic
Wallet scopeAll wallets, or one (only for the worst-position mode; the summary request takes the wallet scope and the server picks the worst)All

Rule. Positions are a searchable entity so Siri, Spotlight and Shortcuts use the same list. Removing a watched position or wallet makes the widget fall back to the worst position, then to the empty state.

Proposed thresholds: stale after 30 minutes without an update, "cannot refresh" after two hours. These are proposals, not decisions.

Refresh

How values get into the widget.

SourceBehaviour
App in the foregroundWrites the snapshot, then asks the widget to reload. Does not use the reload budget.
Background refreshThe app writes a new snapshot when the system allows it.
Timeline reloadThe system gives each widget a limited daily budget; plan for roughly 40 reloads a day, entries at least 5 minutes apart.
PushAfter the MVP. Push updates for a widget supplement the timeline; they need the push infrastructure.
AndroidThe app updates the widget after writing the snapshot; long work goes to a background worker.
LimitsWidgets never bypass plan limits; they read cached data. On-demand refresh limit is the same for every plan.

Rendering modes

The system may restyle a widget. The structure must survive every mode.

ModeConditionStructure rule
Full colourHome Screen defaultSurface and ink come from tokens; the block colour is chosen by the configuration
Accented (tinted)Home Screen tint styleThe system replaces colour with one tint. Status stays a word and a shape. Group parts that take the accent; the rest stays neutral
VibrantLock ScreenSingle colour with levels of opacity. Contrast is checked across the lightest and darkest wallpaper
Reduced luminanceAlways OnDimmed; text must stay legible
Transparency changesSystem glass or opacity settingNo part of the structure relies on a particular background

Rule. The widget draws its own background as one removable group, so the system can remove it without breaking the layout.

Accessibility

A widget is read as one sentence and opens one place.

ItemRule
Spoken labelOne sentence: pair, status, total, range, owed fees. Example form: "ETH / USDC, in range, total, price inside the range, owed fees in each token".
Text sizeText follows system text size where the family allows it. At the largest sizes secondary details drop before the total, status or fees do.
ContrastEvery ink and surface pair passes in every mode, including both ends of the system glass setting.
MotionNo animation that carries meaning. Values change on reload.
TargetsThe tap target is the whole widget.
TestsSnapshots per family, mode, theme and text size; a manual pass with the glass setting at both ends and Always On.
