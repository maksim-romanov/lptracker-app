Landing wireframe, v2

Built from parts, so the page can grow

The page is a stack of sections on one grid. The first screen is one section (Hero). Every part has a name, a size rule and states, so a new section reuses them instead of starting over. Mobile is drawn first because it is the hardest case.

Foundations

Decide these once. Everything below follows them.

Grid

12 columns, 1200 maxgutter 24
8 columns, tabletgutter 20
4 columns, phonegutter 16

Spacing scale

4, 8, 12, 16, 24, 32, 48, 64. Nothing off the scale. Section padding is 64 on desktop, 48 on tablet, 32 on phone.

Side margin: 56 desktop, 32 tablet, 16 phone, plus the device safe area.

Breakpoints

Phone up to 599. Tablet 600 to 899. Desktop 900 and up. Large 1600 and up (content stops growing at 1560).

Plus one height rule: landscape phone, height 520 or less.

How this wireframe is kept scalable

One name per part

The same part keeps the same name in the component list, the key and the code, so a change is made once.

Rules, not pixels

Sizes are written as rules with a range. Pixels appear only where they are a minimum, such as a 44 px touch target.

States listed up front

Every interactive part lists its states before it is drawn: default, hover, pressed, focus, error, empty.

What changes per width

Each breakpoint states only what differs: stacked or side by side, what is hidden, where the primary action sits.

Mobile first

The phone layout is the base. Larger widths add, they do not rescue.

Placeholders, not content

Boxes and lines stand for content. Final copy and colour come after structure is agreed.
