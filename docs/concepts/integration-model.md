# Integration model

What a contributor adds and how the system finds it ([ADR 0006](../decisions/0006-integration-unit.md)). Steps: [add a protocol](../guides/add-a-protocol.md), [add a chain](../guides/add-a-chain.md). MVP families: `uniswap-v3` and `uniswap-v4`. Aerodrome and Velodrome come after the Aero launch through a research gate ([research/aero](../research/aero/audit-notes.md)).

## Promise

- An integration PR touches only `integrations/**` and the app files below. CI path scope is an allowlist and fails on any other path, so core packages (`packages/core`, `packages/contracts`, `packages/infra`), `packages/integration-kit` and gate config never change for an integration (*planned*, [ADR 0036](../decisions/0036-integration-trust.md)).
- Every app shows a new integration with no change, through the display descriptor.
- App changes are optional and from this list only: translations for new `labelKey`s, a bundled logo, a family-specific view on top of generic rendering. CI flags them for app owners.

The promise holds inside this envelope: **EVM chains, existing position kinds, existing index source kinds and existing staking plugin kinds**. A new position kind, index source kind, staking plugin kind or VM is a change to `integration-kit` or core, reviewed like core.

## Layout

```
integrations/
├── chains/eip155-8453.json
├── protocols/<family>/
│   ├── manifest.json
│   ├── adapter.ts                          new family only
│   ├── deployments/<protocolId>@eip155-8453.json
│   ├── quality.yaml
│   ├── cassettes/                          maintainer-signed recordings
│   ├── conformance.gen.test.ts             generated
│   ├── adapter.test.ts                     snapshots of test wallets, by hand
│   └── README.md                           methodology, written by hand
└── subgraphs/<family>/                     only where no cheaper index exists
```

## Chain file

`caip2`, `slug`, `vm`, `name`, `nativeCurrency`, `wrappedNative`, `multicall3`, `readPolicy` (`{ tag: safe | finalized | latest }`), `requiresArchive`, `maxIndexLagBlocks`, `maxHeadLagBlocks`, `snapshotTtlSeconds`, `blockTime` (seconds, measured; the lag fields derive from it), `publicRpcs`, `explorer` URL templates, `priceIds`, `logo`, `status` (`active`, `deprecated`). URLs are https only and maintainer-allowlisted. `logo` is fetched by the worker through the logo pipeline; `/api/v1/meta/chains` returns `logo: { hash }`. Never deleted.

`priceIds` holds the DefiLlama chain slug and the CoinGecko platform id. Chainlink feeds (core assets plus, on L2s, the `sequencerUptime` feed) live in `integrations/chains/<chain file>.feeds.gen.json`, generated by `bun run codegen` (*planned*) from Chainlink's reference data; each feed records that data URL as its source ([prices and logos](prices-and-logos.md#chainlink)).

## Manifest

| Field | Meaning |
|---|---|
| `family`, `name` | Family identity, e.g. `uniswap-v3` |
| `extends` | Present for a fork: the family it reuses |
| `overrides` | Fork differences: `abi`, `poolDerivation` (factory + init code hash per deployment), `structShapes` (e.g. `slot0`, `positions()` tuples), `feeTiers` |
| `positionKinds` | e.g. `concentrated-lp` |
| `revertTexts` | Revert texts that mean the position token no longer exists, matched case-insensitively ([data rule](data-rule.md)) |
| `dependencies` | What an instance must provide: `rpc:archive`, `subgraph:thegraph`, … Missing → scope `not_configured` |
| `lifecycle`, `qualityTier` | See [state model](state-model.md) |
| `owners` | At least one person, as GitHub handles; a bot mentions them on changes |
| `kitApiVersion` | integration-kit version targeted |

Three shapes, chosen by the fit gate: **pure fork** (`extends`, deployments only), **fork with overrides**, **new family** (own `adapter.ts`). A fork with a different position struct or custody model (for example Slipstream's `tickSpacing` instead of `fee`) is a new family.

## Deployment

| Field | Meaning |
|---|---|
| `protocolId` | e.g. `uniswap-v3` |
| `contracts[]` | Role tuples: `{ role, address, fromBlock, toBlock?, source }`. A protocol with several generations (redeploys, several factories) lists one tuple per generation; each position manager is its own entry. Unknown values stay `TODO`. |
| `index[]` | One or more index sources, tried in order |
| `staking` | `{ kind: none | v3-staker | gauge | masterchef, contracts }`; reward tokens are read from the staking contract, never listed |
| `status` | `active`, `read-only`, `sunset` |
| `supersededBy` | Deployment id of the protocol's new contracts |

Endpoints, keys and RPC URLs never appear here; `instance.config` maps what a deployment declares to what an instance has ([ADR 0013](../decisions/0013-official-and-self-hosted-instances.md)).

## Adapter

`adapter.ts` does `export default defineProtocol({ … })`, which builds a `ProtocolAdapter` (the port in `packages/core`). A new family implements two calls; core supplies everything else through the `AdapterContext`:

| Call | Returns |
|---|---|
| `discover(ctx, owners)` | `PositionRef[]` with `seenAtBlock` from the deployment's index sources |
| `snapshot(ctx, refs)` | Verification results and `Position[]` with extension and display descriptor, read at `readBlock` |

The context gives a `PinnedChainReader` (a `ChainReader` fixed to `readBlock`), the configured index sources, which reach subgraphs only through the `IndexTransport` port, the staking plugin, a logger and a clock. Adapters never create clients, never touch a database or the network directly, and never branch on `protocolId` ([ADR 0036](../decisions/0036-integration-trust.md)).

## Index sources

| Kind | Use for | MVP users |
|---|---|---|
| `rpc-enumeration` | ERC721Enumerable position managers and farms | Uniswap V3 |
| `rpc-logs` | Owner-filtered `Transfer` logs; on a request it only fills the gap behind a working index, the worker backfills from `fromBlock`; no key needed | Uniswap V4 gap fill |
| `aggregator` | A protocol contract that lists an owner's positions | none (Sugar after the Aero launch) |
| `subgraph-third-party` | Someone else's subgraph mapped to refs | Uniswap V4 |
| `subgraph-own` | Our subgraph in `integrations/subgraphs/`, written from scratch | none |

Subgraph rules:

- Queries are always batched by owners (`owner_in`, at most 100 owners, lowercase), paginated, and read `_meta.block` as `indexBlock`.
- Refs are cached for 15 minutes with the last good value; `rpc-logs` fills the gap to `readBlock`. This keeps the official instance inside The Graph free tier ([providers-and-cache](providers-and-cache.md)).

Uniswap V4 mapping: the official `v4-subgraph` gives `tokenId` and `owner` only. The adapter then reads `PositionManager.getPoolAndPositionInfo(tokenId)` and `getPositionLiquidity(tokenId)`, and `StateView.getPositionInfo(poolId, PositionManager, tickLower, tickUpper, bytes32(tokenId))`, all at `readBlock`.

## Staking plugins

| Plugin | Status | Custody | Fee accrual | Rewards |
|---|---|---|---|---|
| `none` | MVP | `wallet` | `claimable` | none |
| `v3-staker` | planned | `v3-staker` (`deposits(tokenId).owner`) | `claimable` after withdrawal | incentive rewards |
| `gauge` | after the Aero launch | `gauge` | `redirected`; fee math skipped | `rewardToken()` read from each gauge |
| `masterchef` | planned | `masterchef` | `claimable` | pending reward token |

## Generated from manifests

| Artifact | How |
|---|---|
| Registry of families | Built at build time, not committed |
| Support matrix in docs | Built into the docs site |
| `CODEOWNERS` (maintainers only), app metadata snapshot | Committed by a bot after merge |

An integration PR never edits generated files, `AGENTS.md`, `CLAUDE.md`, `.agents/`, `.claude/`, `.mcp.json`, `.skills/`, `.agent/` or `.github/workflows/`.
