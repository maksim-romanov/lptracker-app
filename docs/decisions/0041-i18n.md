# 0041 · English by default, translations by label key

- Status: proposed
- Deciders: Maksim Romanov

## Context

Display descriptors come from integrations written by the community, and three clients render them. Numbers and dates must follow the reader's locale without the server rounding values.

## Decision

- English is the default language everywhere.
- The MVP ships English and Simplified Chinese (`zh-Hans`). Chinese text renders in the platform CJK face (PingFang SC on Apple, the system CJK font on Android, a `PingFang SC`, `Noto Sans SC`, `Microsoft YaHei` stack on the web) behind the brand Latin face ([0055](0055-ghost-design-language.md)).
- Every user-facing string from the server carries a `labelKey` and an English `label`; clients translate by key and fall back to the label ([concepts/position-model.md](../concepts/position-model.md)).
- Catalogs live with each client: server message catalogs for the web, String Catalogs for iOS and macOS, string resources for Android.
- Integrations ship English labels with their keys; translations are optional app changes from the allowed list ([0006](0006-integration-unit.md)).
- The web picks the locale from `Accept-Language`, with a user override.
- Numbers and dates are formatted by platform formatters from the exact decimal strings the server sends ([0003](0003-server-owns-protocol-logic.md)).

## Consequences

- A new family is readable in English everywhere on day one.
- Missing translations never block a release.
- A language that needs Cyrillic or Greek reopens the typeface choice ([typeface](../research/repo/typeface.md)).
