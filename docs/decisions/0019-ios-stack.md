# 0019 · iOS, iPadOS and macOS app stack

- Status: proposed
- Deciders: Maksim Romanov

## Context

One Swift codebase ships to iPhone, iPad and Mac with widgets. Agents edit it constantly, so project files must not produce merge conflicts, and dependencies must be swappable in tests like Riverpod overrides.

## Options

- **Plain Xcode project, TCA**.
- **Tuist, `@Observable` + swift-dependencies + swift-sharing**.

## Decision

Chosen **Tuist with `@Observable`, swift-dependencies and swift-sharing**, because Tuist declares the module graph in Swift and checks implicit imports, and swift-dependencies gives provider-style DI with test overrides without TCA's ceremony. Generated projects also avoid `.pbxproj` merge conflicts; Xcode 27.2's JSON project format weakens that argument, not the first two ([research](../research/ios-app/agent-docs-and-skills.md)).

- Minimums: iOS, iPadOS and macOS 26; Swift 6 strict concurrency; UI modules use MainActor default isolation, `Domain`, `APIClient` and `Data` stay nonisolated ([code style](../concepts/code-style.md#swift)).
- One multiplatform app target (iOS, iPadOS, macOS) plus a widget extension; the app and the widget are the two composition roots.
- Modules `Feature*`, `Domain`, `Data`, `APIClient`, `DesignSystem`, `WidgetUI`, `AppIntentsKit` are Tuist targets, so the graph is declared in one place; `tuist inspect dependencies --only implicit` runs in CI.
- Cache: the last response as JSON in the App Group through `@Shared(.fileStorage)`, keyed per server URL. The app calls `save()` before reloading widget timelines, because implicit saves are delayed.
- The widget reads the app's snapshot and never refreshes tokens; only the app refreshes, so rotating refresh tokens cannot log the person out.
- `APIClient` is generated by the swift-openapi-generator CLI and committed under `Generated/`. Open enums come from `anyOf: [enum, string]`; amounts are formatted from decimal strings, never through `Decimal`, which keeps only 38 digits.
- No SSE in the MVP: ETag polling on foreground and pull-to-refresh.
- Push through a `PushClient` port: OneSignal on iOS and iPadOS, none on macOS in the MVP ([0014](0014-push-via-onesignal.md)).
- App ids, associated domains and the App Group come from one Tuist constant; working value `xyz.depthly.voidx` ([0044](0044-domain-as-configuration.md)).
- UI tests and E2E flows configure Debug builds through launch arguments, never environment keys ([0048](0048-e2e-testing.md)).
- Sign-in: `ASAuthorization` passkeys on the official instance, `ASWebAuthenticationSession` with PKCE on self-hosted instances ([0012](0012-accounts-guests-and-passkeys.md)).

## Consequences

- `Domain` stays pure Swift and imports no Apple UI framework; its tests run through `xcodebuild` on macOS.
- Features only format server-derived values ([0003](0003-server-owns-protocol-logic.md)).
